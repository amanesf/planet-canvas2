## 3. サブエージェントを並列で回すときの規則（前回ここで事故った）

前回7体を並列で回して**5体がセッション上限で同時に全滅**した。
そのうち1体は**半完成の状態を共有ブランチにコミットしていた**。

- **エージェントに git を触らせない。** プロンプトに
  「`git commit` / `add` / `push` / `checkout` / `reset` を一切するな」と
  明記すること。コミットは親が検証してから行う。
- **ファイル所有を完全に分ける。** 前回は `main.ts` を親が持ち、
  各エージェントに1ファイルずつ与えた。新規ファイル系
  （`aurora.ts` / `fog.ts`）は**親が `main.ts` に配線する**約束にした。
- **スクラッチのファイル名とポートも分ける。** `_measure.*` を全員に
  指示したら**取り合いになって上書き事故**が起きた。`_g50.*` のように
  課題ごとに固有名にし、vite のポートも 5201, 5202, … と分けること。
- **途中死は必ず起きる前提で書く。** 「**途中でも報告しろ。正確に説明された
  部分成果の方が、説明のない完成品より価値がある**」とプロンプトに書くと、
  実際に良い報告が返ってくる（空港エージェントは着手前に
  「AIR_ROUTES が export されていない」「港の表がそもそも存在しない」を
  報告して止まった。これが正解）。
- **死体は捨てずにブランチへ退避する。** `wip/agent-salvage`（5体分）と
  `wip/rivers-cancelled`（川・湖）が実例。オーロラは**バッククォートが
  テンプレートリテラルの中にあってコンパイルすら通らない**状態だったが、
  構造と論拠は再投入したエージェントがそこから拾って完成させた。
- **成果は必ず親が呼び出し側まで追うこと。** 前回、空港の差分は
  親が計測し直してから landed（ドローコール 5→7 を自分で確認）。

## 4. 地雷（同じ穴に落ちないこと）

**前セッションで新しく踏んだもの:**

- **加算合成の物を球の手前側に置くと、台座と机の上に光を塗る。**
  オーロラの最初の配線がこれで、球が「台に載った物」ではなく
  「台に重ねた透明画」になった。**リムの向こう側だけ描く**で解決（§2-29）。
- **vite の dev サーバはモジュールをキャッシュする。** before/after を
  同じサーバで測ると**両方同じ数字**が返る。実際にそれで一度、
  意味のない比較をした。**サーバを立て直してから測ること。**
- **`npm run build` は tsc も走らせる。** 並列作業中は他人の未完成ファイルで
  落ちるので、自分の検証は `npx tsc --noEmit 2>&1 | grep -v <他人のファイル>`
  と `npx vite build` に分けると進む。

**引き続き有効な主要なもの（詳細は §2 各節）:**

- **作る前に「画面上で何pxになるか」を計算する。** 球面1ユニット ≈ **108px**。
  **「描かれていない」と「0.3px幅で描かれている」は画面上で同じ**（§2-21）。
- **効果が微妙なものは、まず単色マゼンタに差し替えて「どこに出るか」を撮る。**
  雨・霧・オーロラは全部これで位置と大きさを確認してから本番の値に戻した。
- **Poisson-disc 層は確率で間引いても減らない。距離（間隔）を変える**（§2-23）。
  `SpatialHash` のセルは「使う最大間隔」で作ること。
- **「修正済み」を疑う。** 砂丘のアーモンドは高さだけ直っていて
  平面形が楕円のまま残っていた（§2-23）。
- **風で流れる物の統計は1シードでは比較できない。16シード×惑星一周で平均**（§2-19）。
- **ある系統を直したら、同じ場を消費している別の系統を測り直す**（§2-19）。
- **THREE.Color は linear。遮蔽は掛ける、引かない**（§2-15）。
- **ビルド時に焼いた向き・位置は移流で狂う**（§2-17）。緯度は不変、経度は違う。
- **負の値の分数乗で NaN。three では NaN 行列は何も描かないので、
  バグが「意図した挙動」に化ける**（台風の静穏期がこれだった）。
- 明暗境界は動かない（§2-12）。構図を触ったら必ず再確認。
- 球の画像A/Bは季節アニメで成立しない。机と平面展開図はA/Bできる。

## 5. 計測のやり方（これが本体）

**新しいセッションでは先に `npm ci` が要る。**

`buildTerrainTexture` も `buildClouds` も `buildSpecies` も `buildLandmarks` も
**WebGL を必要としない**。アプリ本体は swiftshader で50〜120秒かかるが、
**ルートに `_xx.html` ＋ `src/_xx.ts` を置いて直接 import すれば数秒で回る。**
変更前の版は `git show <rev>:src/clouds.ts > src/_cloudsOrig.ts` として
同時に import すれば同一プロセスで before/after を比較できる。

- **一時的な引数追加（シード等）は可。コミット前に必ず戻す。**
- インスタンスの「量」は `cbrt(|det|)`（行列式）がスケールに比例する。
- ドローコールは `renderer.info`。**`composer.render()` が info をリセットする**
  ので `renderer.info.autoReset = false`。
- 見た目は Playwright（`/opt/pw-browsers/chromium`、CommonJS なので
  `import pkg from '...'; const {chromium} = pkg;`）。**`page.screenshot` にも
  `timeout` を明示。** 拡大は「撮った png を `<img>` で拡大したページを
  撮り直す」のが速い（PIL は入っていない）。
- **計測フックはコミット前に必ず外し、grep で確認する。**
