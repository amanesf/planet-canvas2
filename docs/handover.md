## 1. いま何が問題か（前セッションの全体レビュー結論）

作者の体感は「まだ30点」。レビューした結論は次のとおり。

> **直近の作業はほぼ全部「データの正しさ」に費やされていて、
> 柱1（物としての説得力）が1ミリも動いていない。**

植生センサス、都市186件、降水量プロキシ、降雪の気候駆動 — すべてが
柱2（一目でどこか分かる）だけを押している。地理的には別物になったのに
見た目が変わらないのはそのため。

**ギャップ一覧が「植生／雲／海／昼夜」とシステム別に整理されているのが罠。**
この順に潰すと、柱1に効く項目（影・質感・光）が毎回別の弾に散らばって
後回しになる。実際、影は G9・G53・G26 の3件に分割されて第4弾と第8弾に
置かれ、3回先送りされていた。

### CGだと露見している要素（damage順）

| # | 症状 | 状態 |
|---|---|---|
| 1 | **影がほぼ存在しない** | 雲影のみ実装（§2-14）。残り2種は未着手 |
| 2 | **全部が同じ「丸い塊」語彙で同じ画面サイズ** | 植生側は `c2452af` で階層化。雲側（G8）は未着手 |

「陸が球の上に乗っているのに下に影も遮蔽もない」を指摘してきた。

## 2. 次にやること

### 第一候補：影の代用の残り2種

レビュー第1位の続き。どちらもレンダリングコストはほぼゼロ。

- **植生の接地陰。** 林冠密度 `canopyAt` は既にあるので、林冠が濃い場所の
  *塗装*（`terrain.ts` の `terrainColor` / `biomeColor`）を暗くするだけ。
  ジオメトリもシェーダも増えない。「陸が球の上に浮いている」読みへの直接の対策。
- **海岸AOの強化。** 現状 `coastalAO` は最大 -0.16、しかも海抜0.006の帯だけで
  ほぼ効いていない。陸が海面シェルに落とす影の代役なので、幅と深さを上げる。

### 第二候補：G8 雲の質感（ちぎった綿）

前セッションでエージェントを立てたが**成果ゼロで停止**させたので
`clouds.ts` は手つかず。効果大だが、モバイル制約（ドローコールを増やさない、
レンダーターゲットを増やさない）が厳しい。`clouds.ts` の既存コメントには
一度チューニング済みのフリンジ／ハローの経緯と、それが直した失敗
（すべての塊に灰色の輪が付く、空で最もCGらしい現象）が書いてある。
**その作業を巻き戻さず、上に積むこと。**

どちらを先にやるかは判断してよい。理由を述べてから進めること。

## 3. 前セッションで踏んだ地雷（同じ穴に落ちないこと）

- **推測で判断せず、§6 の計測フックを仕込んで数字で確認する。**
  着手前と完了後の両方で計測する。前セッションはこれで4回救われた。
- **計測フックと debugcanvas フックはコミット前に必ず外し、grep で確認する。**
- **緯度経度の逆変換は `lon = atan2(z,-x)*180/π - 180`**（-180 を忘れない）。
- **明暗境界は円盤上を掃かない**（§2-12）。光源もカメラも固定で、境界は
  円盤半径の約58%・反太陽側に固定される。**左リム（＝太陽側で最も明るい）を
  見て「夕暮れが出ていない」と誤判定しやすい。** 前セッションで実際にやった。
- **季節アニメーション（1分＝1年）が止められないので画像A/B比較は成立しない。**
  回転は `#mode-toggle` で止まるが季節は止まらず、2回のキャプチャで紅葉の
  フェーズがずれて85%の画素が変化する。やるなら先に季節を止める手段を作ること。
- **並列エージェントはファイル所有を完全に分けること。** 前セッションで
  スコープ外の `eruptions.ts` / `main.ts` を触られ、`windAt` が呼び出し側で
  渡されないまま**「コードはあるが完全に不活性」**な状態が main に乗った。
  正味の効果は「従来の挙動を削除して何も入れなかった」だった。
  **エージェントの成果は必ず自分で呼び出し側まで追って配線を確認すること。**
- **白波を「深度」でゲートしてはいけない**（§2-10）。大陸棚は幅全体が浅いので
  北海・アイリッシュ海・スンダ棚・タイランド湾が丸ごと白くなる。正しい量は
  海岸線からの距離。この種の失敗は**平面展開図に出すまで気づけない**。
- プレビューサーバは pkill と同じコマンドに混ぜない（レースで死ぬ）。専用の
  Bash 呼び出しで単独起動する。`npm run build` は dist を奪い合うので、
  並列時は `npx vite`（devサーバ）を使う。
- Playwright: `executablePath: '/opt/pw-browsers/chromium'`、
  `/opt/node22/lib/node_modules/playwright/index.js` は CommonJS なので
  `import pkg from '...'; const {chromium} = pkg;`。起動は swiftshader で
  50〜120秒、同一ビルドでも大きくブレる。ハングではないのでタイムアウトは
  長めに（240秒以上）。

## 6. 未消化で残っている大物

着手時は §2 の該当節を必ず読むこと。

- **降水量プロキシの消費側がゼロ。** `precipitationAt` /
  `precipitationProfileAt` / `precipitationAtSeason` は完成しているが
  **誰も使っていない**。第3弾の本体（G7 雲を気候から、G34〜37 雨・雪・雷、
  G40、川の流量重み）は手つかずで、§3 の「気象の発生源が一元化されていない」
  という構造問題は土台ができただけで未解決。
- **川がほぼ動いていない**（§2-8）。陸地セルの12.6%がシンク。
  **直すときは堆積扇の時限爆弾に注意** — `deltaCoast` がアマゾンで0.907
  あるので、水系を直した瞬間に砂色が盆地を3,000km内陸まで塗る。
  §2-8 に対処法あり。
- **都市の実体化**（G43〜G46）。ただし**186都市のうち26都市の中心座標が
  標高ラスタ上で水**なので、建物を正確な座標に置くと海に建つ（§2-11）。
- G5 地域アイコン、G6 砂丘の実座標配置、第6弾 波の作り直し。
