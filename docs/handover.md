## 2. 次にやること

### 第一候補：海まわり3件をまとめて（G14 → G17 → G16）

**残件で唯一「効果大 × コスト小」があるのがここ**（G14）。しかも3件とも
同じシェーダ・同じメッシュを触るので、検証も撮影も1回で済む。

- **G14 うねりの解像度** — 1波長あたり2.7頂点しかなく、振幅が半径の1/1000。
  波が「ある」ことになっているが画面では平ら。**着手前に画面上で何pxに
  なるかを計算すること**（下記 §3 の教訓）。
- **G17 海メッシュ** — 76×44。陸は 384×216 なので、海岸線がカクつく。
- **G16 サングリント** — 今は環境マップ由来の静止した塊。太陽方向に応じて
  動く筋にする。**鏡面は海シェルにしかない**（§2-18）ことを踏まえること。

第6弾（波の作り直し）の G13（帯状風に沿った流れ）もここに繋がる。
**雲の `zonalWind(lat)` がそのまま使える** — 同じ場を2度書かないこと。

### 第二候補：第3弾の残り（積雪・川）

- **G38 積雪 / G37 降雪域の移動** — 雪線（塗装）と雪片が今も別系統。
  **雲影マップにはアルファチャンネルがまだ空いている**（R雲・G移流・B雨、
  §2-22）。「今雪が降っている所」を焼く先として使える。ドローコール0本で済む。
- **川の流量重み**（§2-8）。**堆積扇の時限爆弾に注意** — `deltaCoast` が
  アマゾンで0.907あるので、水系を直した瞬間に砂色が盆地を3,000km内陸まで塗る。

### 第三候補：彩度（レビュー第4位の残り半分）

**判断が要るので据え置いてある。着手前に §9 を読むこと。** この作品は過去に
一度「全体的にトーンダウン」して**洗いすぎた**と判断し、**意図的に彩度を
上げ直した経緯がある**。つまり「彩度を下げる」は記録済み判断の巻き戻し。

- 下げるなら**塗装ではなく植生インスタンス側**（`species.ts` の `canopyClimate`）。
- **必ず3Dレンダで判断すること**（平面展開図では植生が地面を隠す）。
- 露出 `toneMappingExposure=1.9` は夕暮れ帯と街の灯りが同時に動く。単独で触らない。

どれを先にやるかは判断してよい。**理由を述べてから進めること。**

## 3. 地雷（同じ穴に落ちないこと）

**前セッションで新しく踏んだもの:**

- **作る前に「画面上で何pxになるか」を計算すること。**
  このカメラでは球面1ユニット ≈ **108px**（`760 / (2 * 9.6 * tan20°)`）。
  稲妻は実寸で0.3px幅で、**「描かれていない」と「細すぎる」は画面上で同じ**。
  **`project(camera)` で描画位置を吐かせるのが一番速い**（それで初めて
  「描けているが白い綿の上だった」と分かった）。
- **Poisson-disc 層は「確率」で間引いても減らない。** 閉じた林はパッキング
  律速なので、候補を棄却しても次の候補が同じ場所に入る。実測で
  「44%間引いて2%しか減らない」。**距離（間隔）を変えること**（§2-23）。
- **「修正済み」を疑うこと。** 砂丘のアーモンドは §2-13 で直したことに
  なっていたが、直っていたのは高さだけで**平面形は楕円のまま**だった。
  球を1軸に伸ばした形は、y に何をしても上から見ればレンズ。
- **雲・雪など「風で流れる物」の統計は、1つの RNG シードで前後比較しても
  意味がない。** 帯は惑星全体で10本しかないので、**どの10箇所に当たったかが
  規則の差より大きい。** 最初の1シード比較は「砂漠好きが4倍になった」と出し、
  同じコードが別シードでは逆を出した。**16シード × 惑星一周で平均すること。**
- **生のシェアで比べない。単位面積あたりの濃縮率で比べる。**
  生のシェアは「単にバンドを少なく置いた版」を有利に見せる。
- **ある指標を直したら、同じ場を消費している別の系統を必ず測り直す。**
  雲を降水量に繋いだ第1版は砂漠指標では最良だったが、**同じ変更が
  雪の上の空を消していた**（雪地点の雲量 0.0011／全球 0.055）。
- **ケッペン的には極冠は砂漠**（氷床の年降水量はサヘルより少ない）。
  降水量をそのまま「雲量」「湿り気」に使うと極が壊れる。
- **球を外から見る限り、セルの真下に置いた物はほぼ常に自分の雲の裏。**
  「実装が動いていない」のではなく「見える場所に無い」ことがある。
  **単色（マゼンタ）に差し替えて描画の有無を先に確かめること。**
- **負の値を分数乗すると NaN。** three では NaN 行列は何も描かないので、
  **バグが「意図した挙動」に化けて何ヶ月も残る**（台風の静穏期がこれだった）。

**従来からのもの（引き続き有効）:**

- **推測で判断せず計測フックを仕込む。着手前と完了後の両方で測る。**
- **計測フックはコミット前に必ず外し、grep で確認する。**
- **`THREE.Color` は linear 空間。遮蔽は「引く」ではなく「掛ける」。**
- **ビルド時に焼いた向き・位置は移流で狂う。** 緯度と方位角は不変、経度は違う。
- **`MultiplyBlending` は `premultipliedAlpha` が要る**（無いと机に白い紙が乗る）。
- **`SpatialHash` のセルは「使う最大間隔」で作る**。可変間隔で使うと
  静かに近傍を取りこぼす（§2-23 で実際に踏みかけた）。
- 緯度経度の逆変換は `lon = atan2(z,-x)*180/π - 180`。
- 明暗境界は円盤上を掃かない（§2-12）。**構図を触ったら必ず再確認。**
- **球の画像A/Bは季節アニメで成立しない。机と平面展開図はA/Bできる。**
- 並列エージェントはファイル所有を完全に分けること。**成果は必ず自分で
  呼び出し側まで追うこと**（レート上限で途中死する）。
- 白波を「深度」でゲートしてはいけない（§2-10）。正しい量は海岸線からの距離。
- プレビューサーバは pkill と同じコマンドに混ぜない。並列時は `npx vite`。

## 4. 計測のやり方（これが本体）

**新しいセッションでは先に `npm ci` が要る。**

`buildTerrainTexture` も `buildClouds` も `buildSpecies` も **WebGL を
必要としない**（canvas 2d と行列だけ）。アプリ本体は swiftshader で
50〜120秒かかるが、**ルートに `_measure.html` ＋ `src/_measure.ts` を置いて
直接 import すれば数秒で回る。** 変更前の版は
`git show <rev>:src/clouds.ts > src/_cloudsOrig.ts` として同時に import すれば
同一プロセスで before/after を比較できる（前回は3版を同時に測った）。

- **シード比較のために `buildClouds(radius, season, seed = 4242)` のような
  引数を一時的に足してよい。コミット前に必ず戻すこと。**
- インスタンスの「量」は行列式から測れる: `cbrt(|det|)` がスケールに比例。
- ドローコールは `renderer.info`。**`composer.render()` は info をリセットする**
  ので `renderer.info.autoReset = false` にすること。
- **見た目の確認は Playwright**: `executablePath: '/opt/pw-browsers/chromium'`、
  `/opt/node22/lib/node_modules/playwright/index.js` は CommonJS なので
  `import pkg from '...'; const {chromium} = pkg;`。起動は 50〜120秒ブレる。
  **`page.screenshot` にも `timeout` を明示すること。**
- **拡大して見たい所は、撮ってから `<img>` を拡大したページを撮り直すのが速い**
  （PIL は入っていない）。
- **効果が微妙なものは、まず単色に差し替えて「どこに出るか」を撮る。**
  §2-22 では海の diffuse をマゼンタにして斑の位置と大きさを確認してから
  本番の値に戻した。§2-21 の教訓の実践。

## 7. 未消化で残っている大物（全32件は gap-analysis §4）

着手時は §2 の該当節を必ず読むこと。

- **海まわり**（G14/G17/G16/G13）— 上記 §2 第一候補。
- **G5 地域アイコン**（バオバブ・桜・サボテン等を実座標に）、**G6 砂丘の実座標配置**。
- **都市の実体化**（G43〜G46）。**186都市のうち26都市の中心座標が標高ラスタ上で水**
  なので、正確な座標に置くと海に建つ（§2-11）。
- **川（G27）・湖（G28）** — 堆積扇の時限爆弾に注意。
- **彩度**（§9 の記録済み判断の巻き戻しになる）。
- **雲の材質感**（§2-17 の残り）。ズームすると「毛羽立った綿」ではなく
  「滑らかな白い小石」。**ハローは灰色の輪という最悪の失敗を一度直した
  経緯がある**（`clouds.ts` 冒頭）。当てずっぽうで触らないこと。
- **雲影テクスチャは静的**（§2-19/§2-22）。雲の大きさを降水量で変えても影は
  変わらないので、`coverageFor` の下限 0.35 はこの制約から来ている。
  0にすると**砂漠に影だけが残る**。アルファチャンネルはまだ空き。
- **鏡面は海シェルにしか無い**（§2-18）。「岩だけがマット」は既存の明示的判断。
- **起動時間 50〜70秒**（G32）。テクスチャ焼きがCPU律速。
