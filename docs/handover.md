## 1. 前セッションで何が終わったか

**地球儀のマウント（地軸・子午線環・浮かせ）。ユーザーからの直接の依頼で、
§2 の候補リストからではない。** 全計測値は §2-31。

| | 値 |
|---|---|
| 球を持ち上げた量 | **0.26ユニット = 3.0cm = 30px**（縮尺は小物5種から 1u≈11.5cm） |
| 地軸 | 0.04ラジアン → **23.4°** |
| 環の半径 | **2.66**（不透明な雲2.540・ハロー2.615を実測して決めた） |
| 環が球面から立つ高さ | 0.66u = 7.6cm = **76px** |
| カメラ | 9.6 → **10.2**（ピンが上端から17px→40px） |
| 明暗境界 | 0.568 → 0.558（**1.1px**。§2-12 は健在） |
| ドローコール | 162 → **163**（+1） |

**この作業で見つけた既存バグ2つ（どちらも §2-31 に詳細）:**

- **`globeGroup` は既定の Euler 順で歳差していた。** z=傾斜・y=自転を
  既定の XYZ で合成すると極が円錐を描く（半回転で **46.8°**）。傾斜が
  0.04ラジアンの間は誰にも見えなかった。`rotation.order = 'ZYX'` で修正。
- **球を浮かせたらオーロラが台座に緑のリボンを敷いた。** §2-29 の `behind`
  項は球の手前しか消せず、球の**下**は真鍮の襟が塞いでいただけだった。
  ワールド高さで切って修正（`uFloorY`）。

**§9 の「子午線環は復活させないこと」は限定に書き換えた。** 本当の教訓は
「環はダメ」ではなく **「リムをなぞる環はダメ」**。次に環を触るときは、まず
**投影の最接近距離**を測ること（今回は2.542 対 ディスク2.0）。

## 4. 地雷（同じ穴に落ちないこと）

**前セッションで新しく踏んだもの（全部 §2-31）:**

- **three の Euler 既定順 XYZ は Rx·Ry·Rz。** 回転を2つ持つグループは
  **順序を明示しないと意図した軸で回らない。** 小さい角度では見えないので、
  角度を大きくした瞬間に古いバグが牙を剥く。
- **テンプレートリテラル（シェーダ）の中にバッククォートを書くと
  コンパイルが通らない。** 前回の引き継ぎに書いてあったのに踏んだ。
  シェーダ内のコメントで識別子を囲みたくなったら、囲まずに書く。
- **ドローコールは「組み立て後」だけ測る。** `animate()` は球ができる前から
  回っているので、混ぜると min 12 / median 52 / max 163 になる。
  組み立て後だけなら 162/163 で安定。**`renderer.info.autoReset = false`。**
- **平板用に調整したマテリアルを曲面に着せると別物になる。** 銘板の
  metalness 0.55 / env 1.8 を弧に着せたら**蛍光オレンジ**になった。
- **バウンディングスフィアで「どこまで届くか」を測ると細長い物で嘘が出る。**
  雲は最大2.615なのに、球で測ると3.241と出た（＝環の半径を0.6も間違える）。
  **全頂点を変換して測ること。**
- **何かを動かしたら、その物が塞いでいた物を疑う。** 球を3cm上げただけで
  オーロラが漏れた。襟が遮蔽物として働いていたことは誰も書いていなかった。

**引き続き有効な主要なもの（詳細は §2 各節）:**

- **作る前に「画面上で何pxになるか」を計算する。** **カメラが10.2になったので
  約102px/ユニット**（1280×760）。以前の「108〜110px」は9.6のときの値。
  **「描かれていない」と「0.3px幅で描かれている」は画面上で同じ**（§2-21）。
- **効果が微妙なものは、まず単色マゼンタに差し替えて「どこに出るか」を撮る。**
- **Poisson-disc 層は確率で間引いても減らない。距離（間隔）を変える**（§2-23）。
- **「修正済み」を疑う。** 砂丘のアーモンドは高さだけ直っていて
  平面形が楕円のまま残っていた（§2-23）。
- **風で流れる物の統計は1シードでは比較できない。16シード×惑星一周で平均**（§2-19）。
- **ある系統を直したら、同じ場を消費している別の系統を測り直す**（§2-19）。
- **THREE.Color は linear。遮蔽は掛ける、引かない**（§2-15）。
- **ビルド時に焼いた向き・位置は移流で狂う**（§2-17）。緯度は不変、経度は違う。
- **負の値の分数乗で NaN。three では NaN 行列は何も描かないので、
  バグが「意図した挙動」に化ける**（台風の静穏期がこれだった）。
- 明暗境界は動かない（§2-12）。**構図を触ったら必ず再確認。**
  指標は `|sun·viewDir|`（§2-31 に式と検算あり）。
- 球の画像A/Bは季節アニメで成立しない。机と平面展開図はA/Bできる。
- **加算合成の物を球の手前側に置くと、台座と机の上に光を塗る**（§2-29）。

## 5. 計測のやり方（これが本体）

**新しいセッションでは先に `npm ci` が要る。**

`buildTerrainTexture` も `buildClouds` も `buildSpecies` も `buildLandmarks` も
**WebGL を必要としない**。アプリ本体は swiftshader で**90〜110秒**かかるが、
**ルートに `_xx.html` ＋ `src/_xx.ts` を置いて直接 import すれば数秒で回る。**
変更前の版は `git show <rev>:src/clouds.ts > src/_cloudsOrig.ts` として
同時に import すれば同一プロセスで before/after を比較できる。

- **一時的な引数追加（シード等）は可。コミット前に必ず戻す。**
- インスタンスの「量」は `cbrt(|det|)`（行列式）がスケールに比例する。
- **「どこまで届くか」は全頂点を変換して測る。**バウンディングスフィアは
  細長い物で大きく外す（§2-31）。
- ドローコールは `renderer.info`。**`composer.render()` が info をリセットする**
  ので `renderer.info.autoReset = false`。**組み立て後のフレームだけ集めること。**
- 見た目は Playwright（`/opt/pw-browsers/chromium`、CommonJS なので
  `import pkg from '...'; const {chromium} = pkg;`）。**playwright 自体は
  プロジェクトに入っていないので、スクラッチ側に `npm i playwright` する**
  （`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`）。
  **`page.waitForFunction` は `(fn, arg, options)`。** 第2引数に options を
  渡すと既定の30秒のままになる（＝組み立てを待てない）。
  **`page.screenshot` にも `timeout` を明示。**
  拡大は「撮った png を `<img>` で拡大したページを撮り直す」のが速い
  （PIL は入っていない）。**`file://` は読めないので data URI にすること。**
- **フレーム内の位置は撮る前に角度で出せる。** カメラは
  距離10.2・画角40°・polar 0.405π・注視 y=0.15。ある点が画面の上端に
  かかるかは「視軸との角度 ≤ 20°」で判定できる（§2-31 で多用した）。
- **計測フックはコミット前に必ず外し、grep で確認する。**

## 7. Gemini

画像生成とレビューに使える。**残り17回**（4セッション連続で未使用）。

- `gemini-3-pro-image` — 画像生成（背景画像はこれで作った）
- `gemini-flash-latest` — テキスト/画像レビュー
- `gemini-2.5-flash` は404で使えない

**キーは環境変数経由でのみ使い、絶対にコミット・push しないこと。**
プロジェクトの目的（工房ではなく「実物として撮影された手作りミニチュア」）を
明確に伝えたうえで、辛口で具体的に指摘させること。
**雨・濡れ・霧・オーロラ・農地・飛行場に加えて、今回の地球儀マウントが
入った絵で取り直す価値がある** — 「台に載った球」から「軸に刺さった地球儀」に
シルエットが変わったので、前回のレビュー指摘は前提ごと古い。
前回のレビュー指摘（影・構図・彩度）のうち彩度だけが未着手。
