## 1. 前セッションで何が終わったか

**第3弾（気象場の一元化）: 雲（G7、§2-19）と雨（G34、§2-20）が完了。**
G35（雪の分布）は実装済みだったのに一覧の記述が遅れていたので直した。

前セッションの引き継ぎは「彩度」と「気象場の一元化」の二択で、後者を選んだ。
理由：彩度は §9 の記録済み判断（一度洗いすぎたので意図的に上げ直した）を
巻き戻す方向で、しかも判断が3Dレンダの見た目に依存する。気象場は
`precipitationAt` が完成しているのに消費側がゼロという、費用対効果が
最大で判断の要らない仕事だった。

- 緯度（移流に不変）で種を蒔き、経度（不変でない）は毎フレーム・ノジュール単位。
  **熱い砂漠の雲の濃縮率 x1.82 → x1.35**、陸雲の下の降水量 0.364 → 0.446。
- 途中で自分の第1版が極の空を消し、**南極の晴天から雪が降る**状態を作った
  （雪地点の雲量 0.0011／全球 0.055）。雲量＝降水量ではなく
  「空気が保持できる量に対する降水量」に直して 0.0100 まで戻した。
  **砂漠指標は降水量そのままの版（x0.92）が最良のまま**で、これはトレードオフ。
- 副産物で実バグを1件修正：`typhoonCentre` が負の age を分数乗していて、
  **静穏期は台風の256行列が丸ごと NaN だった**（＝静穏期は NaN が何も
  描かないことで偶然成立していた）。
- **雨（G34）**: この作品で初めて雲から何かが落ちた。粒ではなく帳、
  ドローコール +1。**乾燥地の上で降ったフレームは 0/3489**、
  降っている帳の下の平均降水量 0.677（惑星平均 0.393）。
  最初の版は**セルの真下**に垂らしたので、正しく描かれているのに
  球を外から見る限りどこからも見えなかった（マゼンタ単色で発見）。
  風下へ逃がして解決。§2-20。

## 2. 次にやること

### 第一候補：第3弾の続き（雷・積雪・川）

**土台も消費側の実例も2つできたので、ここからは同じ蛇口を開けるだけ。**
`precipitationAt` / `precipitationProfileAt` / `precipitationAtSeason` は
雲と雨が実際に使っている。残りは:

- **G40 稲妻の形は一度作って計測し、不採用にした（§2-21）。**
  因果は完璧（乾燥地への落雷0本）だったが、**実長15〜35px・実太さ0.3px**で、
  太らせると自分の白い綿の上に乗って消える。**同じ実装を書き直さないこと。**
  再訪の条件は §2-21 に書いた。
- **G38 積雪 / G37 降雪域の移動** — 雪線と雪片が今も別系統。
- **川の流量重み**（§2-8）。ただし**堆積扇の時限爆弾**に注意（下記 §6）。

**G36（雲の下でだけ降る）は不可能と計測で確定した。§2-19 を読むこと。**
帯10本の空では全球被覆率が 5.5%（雪地点 1.0%）しかないので、
降雪をゲートすると雪が消える。やるなら雲の総量を増やす話が先。

### 第二候補：彩度（レビュー第4位の残り半分）

**前セッションから据え置き。判断が要るから。** 着手する前に §9 を読むこと。
この作品は過去に一度「全体的にトーンダウン」して**洗いすぎた**と判断し、
**意図的に彩度を上げ直した経緯がある**。つまり「彩度を下げる」は
記録済みの判断を巻き戻す方向。

- 下げるなら**塗装（`terrain.ts` の基準色）ではなく植生インスタンスの側**から。
  `species.ts` の `canopyClimate` が返す saturation と季節ティント。
- **必ず平面展開図ではなく3Dレンダで判断すること**（植生が地面を覆っている）。
- 露出（`toneMappingExposure=1.9`）は夕暮れ帯と街の灯りが同時に動く。
  **単独で動かさないこと。**

どちらを先にやるかは判断してよい。理由を述べてから進めること。

## 3. 地雷（同じ穴に落ちないこと）

**今回新しく踏んだもの:**

- **球を外から見る限り、セルの真下に置いた物はほぼ常に自分の雲の裏。**
  「実装が動いていない」のではなく「見える場所に無い」ことがある。
  **単色に差し替えて描かれているかを先に確かめること**（雨で実際に踏んだ）。
- **さらに、画面上で何pxになるかを先に計算すること。** このカメラでは
  球面1ユニット ≈ 108px（`760 / (2 * 9.6 * tan20°)`）。稲妻（§2-21）は
  実寸で 0.3px 幅で、**「描かれていない」と「細すぎる」は画面上で同じ**。
  **描画位置を `project(camera)` で吐かせて確かめるのが一番速い**
  （実際それで初めて「描けているが白い綿の上だった」と分かった）。

- **雲・雪など「風で流れる物」の統計は、1つの RNG シードで前後比較しても
  意味がない。** 帯は惑星全体で10本しかないので、**どの10箇所に当たったかが
  規則の差より大きい。** 最初の1シード比較は「砂漠好きが4倍になった」と出し、
  同じコードが別シードでは逆を出した。**16シード × 惑星一周で平均すること。**
- **生のシェアで比べない。単位面積あたりの濃縮率で比べる。**
  生のシェアは「単にバンドを少なく置いた版」を有利に見せる。
- **ある指標を直したら、同じ場を消費している別の系統を必ず測り直す。**
  雲を降水量に繋いだ第1版は砂漠指標では最良だったが、**同じ変更が
  雪の上の空を消していた**。雪側を測るまで誰も気づけなかった。
- **ケッペン的には極冠は砂漠**（氷床の年降水量はサヘルより少ない）。
  降水量をそのまま「雲量」「湿り気」に使うと極が壊れる。
  **雲量はミリ数ではなく、空気が保持できる量に対するミリ数。**
- **負の値を分数乗すると NaN。** three では NaN 行列は何も描かないので、
  **バグが「意図した挙動」に化けて何ヶ月も残る。**

**従来からのもの（引き続き有効）:**

- **推測で判断せず計測フックを仕込む。着手前と完了後の両方で測る。**
- **計測フックはコミット前に必ず外し、grep で確認する。**
- **`THREE.Color` は linear 空間。遮蔽は「引く」ではなく「掛ける」。**
- **ビルド時に焼いた向き・位置は移流で狂う。**方位角と緯度は不変、経度は違う。
- **MultiplyBlending は `premultipliedAlpha` が要る。**
- 緯度経度の逆変換は `lon = atan2(z,-x)*180/π - 180`。
- 明暗境界は円盤上を掃かない（§2-12）。**構図を触ったら必ず再確認。**
- **球の画像A/Bは季節アニメで成立しない。机と平面展開図はA/Bできる。**
- 並列エージェントはファイル所有を完全に分けること。**成果は必ず自分で
  呼び出し側まで追うこと**（レート上限で途中死する）。
- 白波を「深度」でゲートしてはいけない（§2-10）。
- プレビューサーバは pkill と同じコマンドに混ぜない。並列時は `npx vite`。
- Playwright: `executablePath: '/opt/pw-browsers/chromium'`、
  `/opt/node22/lib/node_modules/playwright/index.js` は CommonJS なので
  `import pkg from '...'; const {chromium} = pkg;`。起動は swiftshader で
  50〜120秒ブレる。**`page.screenshot` にも `timeout` を明示すること。**

### 速い計測のやり方

`buildTerrainTexture` も **`buildClouds` も WebGL を必要としない**
（canvas 2d と行列だけ）。**ルートに `_measure.html` ＋ `src/_measure.ts` を
置いて直接 import すれば数秒で回る。** 変更前の版は
`git show <rev>:src/clouds.ts > src/_cloudsOrig.ts` として同時に import
すれば同一プロセスで before/after を比較できる（今回は3版を同時に測った）。
**シード比較のために `buildClouds(radius, season, seed = 4242)` のような
引数を一時的に足してよいが、コミット前に必ず戻すこと。**
**使い終わったら消すこと。** 新しいセッションでは先に `npm ci` が要る。

インスタンスの「量」は行列式から測れる: `cbrt(|det|)` がスケールに比例する。

ドローコールは `renderer.info`。**`composer.render()` は info をリセットする**
ので `renderer.info.autoReset = false` にすること。

## 6. 未消化で残っている大物

着手時は §2 の該当節を必ず読むこと。

- **雨・雷（G34/G40）** — 上記 §2 第一候補。
- **川がほぼ動いていない**（§2-8）。陸地セルの12.6%がシンク。
  **直すときは堆積扇の時限爆弾に注意** — `deltaCoast` がアマゾンで0.907
  あるので、水系を直した瞬間に砂色が盆地を3,000km内陸まで塗る。
- **彩度**（上記 §2 第二候補）。
- **都市の実体化**（G43〜G46）。**186都市のうち26都市の中心座標が
  標高ラスタ上で水**なので、正確な座標に置くと海に建つ（§2-11）。
- G5 地域アイコン、G6 砂丘の実座標配置、第6弾 波の作り直し。
- **雲の材質感**（§2-17 の残り）。ズームすると「毛羽立った綿」ではなく
  「滑らかな白い小石」。**ハローは灰色の輪という最悪の失敗を一度直した
  経緯がある**（`clouds.ts` 冒頭）。当てずっぽうで触らないこと。
- **雲影テクスチャは静的**（§2-19）。雲の大きさを降水量で変えても影は変わらない
  ので、`coverageFor` の下限 0.35 はこの制約から来ている。
  0にすると**砂漠に影だけが残る。**
- **鏡面は海シェルにしか無い**（§2-18）。「岩だけがマット」は既存の明示的判断。
